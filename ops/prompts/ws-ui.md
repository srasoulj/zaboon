SPEC: `ws-ui` — build the design system and component kit in `packages/ui`, plus a dev gallery.

Read: docs/DESIGN-SYSTEM.md (all), packages/ui/tokens.json (READ-ONLY contract), CLAUDE.md rule 5 (Persian text). The app is Next.js 16 + React 19 + Tailwind v4; components must work as client components.

DELIVER
1. `packages/ui/scripts/build-tokens.ts` generating `packages/ui/src/styles.css`: CSS custom properties for light + dark (prefers-color-scheme and a `[data-theme]` override), a Tailwind v4 `@theme` block, font stacks, the 3D recipe utility classes (btn-3d, card-3d) exactly per DESIGN-SYSTEM §4.3; a test that the generated CSS is up to date with tokens.json.
2. A WCAG contrast test over every text/background pair (light and dark), honoring large-text rules for `labelLargeOnly` fills (§4.1): all must pass AA.
3. Components (React, typed props, accessible, reduced-motion aware, keyboard support): Button3D (primary, secondary, danger, ghost, locked; loading), ChoiceCard (1–9 hint, aria-pressed), WordTile + TileBank (whole-word tiles; bank→answer line with shared-layout animation via `motion`; grey placeholder left in the bank; the answer line direction comes from an explicit `dir` prop), ProgressBar (highlight stripe, streak glow), FeedbackBar (correct/wrong states, solution slot, CONTINUE), PathNode + UnitBanner + PathLayout (sine offsets from tokens, progress ring, bouncing START bubble, locked/current/completed/legendary), StatPill (streak, coins, hearts) with popover, SpeechBubble + Character (SVG placeholder characters for hodhod and the cast built from rounded geometric shapes in the palette — original designs, nothing resembling Duolingo — with a `mouthOpen` 0..1 prop and a `mood` prop; a Rive-ready interface for later), FaText (renders Persian with lang="fa" dir="rtl", per-token transliteration line under each token, tap-for-hint callback, optional vowel marks; NEVER splits a word into separate styled spans), Modal, BottomSheet, Toast, ConfettiBurst (respects reduced motion).
4. dom tests (`*.test.tsx`, Testing Library) for behavior and a11y of every component.
5. A component gallery at `apps/web/app/(dev)/gallery/page.tsx` showing every component and state (Persian + English samples, light/dark), and Playwright screenshot tests in `e2e/ui/gallery.spec.ts` for desktop (1280×800) and mobile (390×844) viewports. Playwright config/fixtures are orchestrator-owned; if `playwright.config.ts` does not exist yet on main, create your spec so it runs with `pnpm exec playwright test e2e/ui` using a minimal local config inside `e2e/ui/` and note it in the PR.
Fonts: load Nunito and Vazirmatn via `next/font/google` in the gallery page only (the root layout is orchestrator-owned); components reference the CSS variables.
