NEVER read env vars inside the package.
2. tools/content-cli: Wave 0 ALREADY ships `validate`, `build` and `publish --local` (src/load.ts, validate.ts, build.ts, publish.ts, paths.ts, with tests in content.test.ts and publish.db.test.ts). The web app depends on their output: keep the bundle layout (`<out>/<courseId>/v<N>/{manifest,letters,characters,build-info}.json` + `units/<unit>.json`, content-hashed media shared in `<out>/<courseId>/assets/` with `assetsBase: "../assets/"`), `content_versions.bundle_path = "<courseId>/v<N>"`, and the idempotent, advisory-locked local publish. Extend, never break, those tests. Add:
   - `validate`: no distractor (pinned `distractors`, bank tiles) can form a valid answer; normalization lint on fa fields (no ي ك, Arabic-Indic digits, ASCII ? ; ,); every letter has examples that contain it; media sign-off policy (approved sentence audio needs `signedOffBy`, except in content/fixtures which are placeholder tones); warnings for items no level uses.
   - `build`: `pathMigrations` passthrough from an optional `path-migrations.yaml`; a `--check` mode that fails if the output differs from an existing version.
   - `publish --target storage`: uploads `v<N>/` and new assets through a small `Uploader` interface (Supabase Storage implementation reads `SUPABASE_URL`/`CONTENT_STORAGE_UPLOAD_KEY` from the environment; tests use an in-memory uploader) and prints the content_versions INSERT for the release runbook. Never makes the version current (a separate approved step, §4.4).
   - `draft`, `suggest`, `art`, `tts` (read OPENROUTER_API_KEY_BUILD from the environment; refuse without it; write status: draft YAML/media with provenance; respect the budget ledger; `--dry-run` prints prompts and cost estimates); `audio` (ffmpeg loudnorm −16 LUFS, mono 64 kbps mp3, 0.7× atempo slow clip, amplitude envelope JSON); `models check` (queries https://openrouter.ai/api/v1/models, flags newer versions in pinned families, no key needed).
